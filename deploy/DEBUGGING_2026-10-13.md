# 三活动与 16:9 学生端：实现及排查记录

[English](DEBUGGING_2026-10-13.en.md) · [说明](../README.md) · [验证记录](../TEST_REPORT.md) · [部署手册](coze.md)

## 需求与实现

2026-10-13，版本 0.6.0。用户确认教师可编辑题干和选项，三个活动均先提交后看结果；直接在浏览器全屏展示。仅学生端固定 16:9，教师后台保持可滚动的笔记本布局。

- 判断题：正确／错误；选择题：2–6 选项；两者右侧展示人数与比例饼图。
- 词云：每人 1–3 个词、每词最多 12 字，参与者内去重后按人数汇总。全量汇总不依赖分页，返回前 60 个高频词，画布说明实际展示数量，教师列表／CSV 保留完整有效记录。
- 基准画布 1440 × 810，缩放系数为 `min(可用宽 / 1440, 可用高 / 810)`。非 16:9 屏幕居中留边；题干最多 60 字，选项最多 24 字，以约束单屏内容。全屏按钮使用浏览器 Fullscreen API。
- 题目配置按课堂保存。首次提交后锁定题干和选项，即使作品删除也不解锁。新课堂继承配置并重置题目版本；旧课堂、固定链接、会话和记录保持原语义。
- `/api/results` 服务端校验课堂归属、活动、页面开关和本题提交回执。教师查询仍需要教师会话。删除清空正文，并立即排除于饼图、词云和导出。
- 沿用共享 PostgreSQL、短请求同步和教师控制版本校验。没有放宽 Cookie 或 iframe 限制，没有添加外部 AI 或图表依赖。

## 验证范围

- 默认 SQLite：50 项中 46 项通过、4 项 PostgreSQL 专项跳过；本地 PostgreSQL：50 项全部通过。生产构建通过。
- 新增 500 人三活动测试：500 次加入、1,500 次集中提交、1,500 次结果读取；比例、词频、删除后计数正确。使用应用注入请求和本机数据库，**不是生产网关或真实浏览器并发压测**。
- 浏览器验证编辑题目、跨活动独立解锁、未完成前题直接跟随、最长题干／选项／填词、提交后图表、暂停／关闭／恢复、全屏和教师结果切换。
- 验证 1920 × 1080、1366 × 768、1280 × 720、1024 × 768、1280 × 800：学生画布均为 16:9，无整页横向或纵向溢出。词云布局有独立的边界、碰撞、稳定性测试。
- 仅使用隔离 QA 和独立演示数据。原本地预览数据没有修改；本轮没有操作扣子生产数据库、密码、实例或发布。

## 快速复现

```bash
npm ci
npm run check
# 只使用隔离测试库，不使用正式生产数据库。
TEST_DATABASE_URL=postgresql://127.0.0.1:55439/classroom_test npm test
node scripts/qa-server.js
```

QA 在本机 3219，密码由脚本输出，数据放入新建的忽略目录。用独立学生浏览器上下文打开教师复制的固定链接。先检查右侧锁定；选择但不提交时仍锁定；提交后出现图表。教师切换后重新锁定，学生再次提交才解锁。依次验证三个活动，并试验暂停、关闭和恢复。

最大版式案例：设置 60 字题干、6 个各 24 字选项，新学生保持学校／姓名未填；词云使用 3 个各 12 字的词。调整上述五种窗口，检查卡片、按钮、文字和图表。原 `test/browser/flow.js` 是 0.5 旧发现／设计流程的历史脚本，不作为 0.6 三活动的验收结果。

## 升级与回退

1. 备份实际部署数据库，停止课堂写入。保留平台 `.coze`、环境变量和数据库绑定；不要用演示数据替换生产数据。
2. 拉取包含 0.6 的提交并构建，沿用原数据库启动。自动升级只扩展提交类型约束，旧内容、课堂 ID、教师密码及登录会话保留。多实例 PostgreSQL 初始化受共享锁保护。
3. 检查实际域名 health 为 0.6.0，登录并刷新教师页；核对原固定链接。旧发现／设计活动仍兼容，新活动在教师端直接选择。新题目的首次提交会锁定内容，演练请使用独立课堂。
4. 升级后的生产验收必须实测三个活动、提交门槛、切换、删除后的图表与 CSV；本地结果不能替代生产验收。本轮未重新执行 0.5 的双进程 HTTP 压测，历史证据仍见旧记录。
5. 回退前停写并备份新增答案。0.5 不理解新活动，不应只回滚代码后继续接收作答；需处理新活动数据并恢复匹配的代码／数据库备份。不要清库修复约束错误。

本轮代码、测试和脱敏记录提交到 GitHub；是否合并以 PR 和远端 `main` 状态为准，发布代码不代表扣子已经部署。
