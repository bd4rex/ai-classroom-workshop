## 起点与故障判断

用户在扣子部署后遇到正确密码登录却又显示未登录、固定学生链接偶尔找不到课堂，以及教师长期提示恢复实时连接。需求是 300–500 名学生同时上课，保持教师推进、每主题先提交再看分享的既有规则。

| 检查 | 实际证据 | 判断和边界 |
| --- | --- | --- |
| 生产顶层标签页登录 | 当时登录及后续会话请求成功，未捕获间歇失败 | 单次成功不能证明跨实例状态一致 |
| 两份独立 SQLite 服务 | A 登录后，B 不能识别同一 Cookie | 本地复现了会话分裂机制 |
| 扣子部署配置 | 1 核／2 GB、最多 2 实例、每实例并发 100；生产 SQLite 在 `/tmp/ai-classroom-data` | 每实例自己的数据库，临时目录也不能承担持久保存 |
| 数据库面板 | 本次检查时没有集成数据库；创建默认开发 PostgreSQL 后连接成功 | 开发库和生产库分开，开发连接成功不代表生产连接成功 |
| 预览 iframe | Cookie 可能受浏览器跨站限制；已有代码分支曾放宽 SameSite | 改 Cookie 不能解决不同 SQLite 之间的会话分裂；保留 Strict，使用顶层标签页和明确错误提示 |
| 长连接 | 旧版使用 SSE；500 名学生可能长期占住 500 个请求 | 托管多实例改为 2.5–3.5 秒短请求同步，不依赖网关支持 SSE |

## 实施顺序与失败记录

1. **先建立共享数据边界。** 在 `server/database.js` 抽出异步 SQLite／PostgreSQL 访问层；共享课堂、会话、身份与提交。事务固定使用同一个池连接；初始化加锁，教师控制与学生提交采用相容的事务锁，避免先检查后写入的竞争。原 SQLite 路径继续可用。
2. **修复登录表象。** 登录和加入后读取会话确认成功；无效 JSON、HTTP 200 HTML 错误页不再当作“未登录”。Cookie 受限时显式报错，学生不自动循环加入。多可信来源通过 `PUBLIC_URL` 配置，保留 HttpOnly 和 SameSite=Strict。
3. **减少请求和写入。** PostgreSQL 使用有随机间隔的短请求同步；作品列表只在版本变化时刷新。学生会话距到期少于 12 小时才续期写库，避免每次轮询写入。每实例数据库池最多 10 个连接。
4. **第一轮本地检查通过。** 提交 `8e78303` 包含共享库、迁移脚本、浏览器恢复检查和 500 人 HTTP 压测。只说明本地通过，随后继续在扣子开发环境验证。
5. **扣子第一次数据库检查暴露并发问题。** 在独立检出目录和隔离 `test_*` schema 执行 `pnpm run check`：39 项通过、1 项失败，150 人同时加入的用例收到 `INTERNAL_ERROR`。源码检查发现加入／提交都会更新同一课堂行，使多用户写入排队。测试没有保留明确的数据库 SQLSTATE，不能把“池获取超时”的推断当作已捕获的日志事实。
6. **消除共享行的写入竞争。** 提交 `6d511e9`：加入不再修改作品版本；PostgreSQL 提交和删除追加 `room_changes` 回执，不争用同一课堂行；版本使用已提交回执的 `COUNT`，避免 `MAX(sequence)` 漏掉较晚提交的低序号事务。连接等待上限由 5 秒改为 10 秒。并发回归扩大到 500 人、两轮 1,000 份提交，并增加乱序提交可见性检查。
7. **扣子实际 PostgreSQL 复测通过。** 同一开发环境使用平台注入的标准 PG 变量，40 项通过、0 项失败，总测试耗时约 64.7 秒；500 人、1,000 份提交用例约 10.8 秒。这里是应用注入测试与真实云数据库，尚未经过生产网关的 500 人真实浏览器访问。
8. **本地真实 HTTP 再压测。** 两个独立 Node 进程、500 个独立 Cookie、两轮集中提交、持续轮询 60 秒，13,688 次请求，0 次非预期错误，峰值 523 个在途请求。保留脱敏的 [机器可读结果](evidence/load-2026-09-23.json)；延迟和操作含义见验证记录。
9. **浏览器故障脚本纠正。** 首轮 Cookie 拦截模拟受到 Playwright `route.fetch` 自动写入 Cookie 的副作用影响，另有学生错误文案定位不匹配；调整模拟和定位后通过。它们属于测试脚本问题，没有据此虚报产品缺陷。
10. **开发沙箱迁移。** 停止已确认的 5000 端口应用进程，备份 SQLite 主文件与 WAL／SHM、平台配置、环境配置和原源码。只读预检后一次性事务导入开发 PostgreSQL；逐表比较所有源字段，全部一致。保留 7 个课堂、343 个参与身份、16 份提交，以及 11 条教师会话和 2 条元数据。未改变教师密码，未重建课堂链接。备份仅留在项目私有 `data/backups/v050/`，不进 Git。

### 开发沙箱遇到的操作问题

- 创建数据库后，旧终端尚未取得新注入的 PG 环境变量。重连开发沙箱、打开新终端后，检查变量名称的存在性，再用 `pg.Pool()` 验证连接。不要通过输出完整环境变量或连接串排查。
- Web 终端的逐字输入会把多行 heredoc 拼到一行。退出未完成输入后改用单行命令；没有完成执行的输入不计作迁移或验证成功。
- 临时验证目录是功能分支的单分支检出，`git fetch origin main` 只更新 `FETCH_HEAD`，没有创建 `origin/main`；第一次归档因此报 `not a valid object name`，未覆盖工作区。同步改用 `git archive FETCH_HEAD -o /tmp/workshop-upstream.tar`，成功后才解包，避免管道末端掩盖前一步失败。平台的 `.coze`、环境文件、私有交接规则和数据需单独保留。
- `pg` 提示未来版本对某些 `sslmode` 的语义将变化。当前连接和测试成功；未关闭 TLS 或证书验证。升级 `pg` 时重新核对平台 TLS 配置，不能为消除警告设置 `rejectUnauthorized: false`。
- 开发进程需限定 `--watch-path=./server --watch-path=./config`，不能用裸 `--watch` 监听 Vite 临时文件，避免构建与重启互相触发。本次将相同约束纳入上游 `npm run dev` 和扣子配置模板。
