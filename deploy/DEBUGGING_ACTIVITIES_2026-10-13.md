# 可增删课堂活动：实现与升级记录

[English](DEBUGGING_ACTIVITIES_2026-10-13.en.md) · [说明](../README.md) · [验证记录](../TEST_REPORT.md) · [部署手册](coze.md)

## 需求与行为

2026-10-13，版本 0.7.0。教师可以为同一节课添加、删除和排序活动，类型固定为判断题、选择题、词云，同一种类型可重复添加。用户确认删除活动时同时永久删除其全部提交。

- 每节课可安排 0–50 个活动；默认保留原三个示例。教师在“本节课的活动”添加、编辑、上移、下移、开始或删除。
- 每个活动的题目、提交回执、阅读门槛、统计和删除锁独立。已提交第一道判断题，仍须提交第二道判断题才能看第二道的饼图。
- 一旦收到提交，锁定该活动的题干和选项；教师可另添同类型活动。暂停、关闭、等候和结束沿用原规则，未交上一题的学生直接跟随下一活动。
- 删除有确认框，会清除全部提交和已移除回执；当前活动被删后全班回到等候页。删除其他活动不改变当前活动或其他题的答案。清空活动后刷新、重启和新建课堂都不会重新填入默认示例。
- 排序不改变活动身份、结果或当前题。新增活动不会复用已删除的 ID。新课堂继承活动顺序和题干，重置题目版本，保留旧课数据并产生新课堂链接。
- 学生端继续固定 16:9；顶部用“当前序号 / 总数”代替固定三个标签。教师记录区用活动下拉列表筛选；CSV 追加活动 ID、序号和题干，区分同类型题目。
- 结束后的课堂不能继续增删编辑；使用课堂工具开始新课堂。原发现／设计活动保留兼容，不作为新增类型。

## 数据与并发

`activities:<课堂ID>` 元数据从按类型索引的对象升级为有序数组，每项包含 `id`、`kind`、`question`、`options`、`revision`。旧对象读取时规范化；旧三题的 ID 保持原类型名。空数组是有效配置，不能回落默认值。

`submissions.activity_id` 回填原 `kind`，唯一约束改为 `(participant_id, activity_id)`。`kind` 仍保留类型约束。SQLite 在事务内重建提交表并保留自增高水位；PostgreSQL 在初始化 advisory lock 内回填字段、删除旧唯一约束并建立新索引。SQLite → PostgreSQL 迁移工具兼容旧表和新活动数组。

活动增删、排序、编辑使用教师鉴权、当前课堂排他锁和 `room.revision` 校验；学生提交使用当前课堂共享锁和参与者锁。删除与提交串行确定先后：先成功的提交随后被删除，或删除后提交得到 404，不产生孤立提交。统计与导出通过一致性快照读取。

接口中原有 `:kind` 和 `?kind=` 参数名为兼容入口而保留，现在传活动 ID；真实类型从活动配置解析。新增 `POST /api/teacher/activities`，接受 `add` / `reorder` / `delete`，删除还要求 `confirm: true`。教师切换的 `stage` 为活动 ID。单人提交限流改为每分钟 120 次，允许一节课的多道题及合理重试。

## 验证与排查

- SQLite：56 项中 51 通过、5 项 PostgreSQL 专项跳过；共享 PostgreSQL：56 项全部通过。生产构建与语法检查通过，无新增依赖。
- 新增覆盖：同类型三种活动独立作答与门槛、配置锁、CSV 区分、活动数量上限、无效排序、过期操作、删除和空列表、继承和旧链接隔离、0.6 SQLite／PostgreSQL 升级、双实例排序竞争及删除／提交竞争。
- 原 500 学生／1,500 份新三类活动提交用例在两种存储回归通过；它使用应用注入和本机数据库，不代表扣子生产网关的容量验收。
- 首轮旧 SQLite 迁移测试失败：测试构造旧表时用 `SELECT *`，新表增加了一列。改为显式列出旧七列，仍检查旧字段全部保留、会话可用和自增高水位；通过。正式迁移也显式列出来源字段。
- 独立 3219 QA 浏览器实测：添加三种类型、同类型判断题、编辑选项、上移、教师切换、逐题提交后解锁、独立饼图／词云、删除确认提示、空列表和刷新。永久删除和批量清空通过测试服务 API 操作合成数据，并观察师生页面同步结果。
- 学生页面在 1024 × 768 和 1366 × 768 下保持 16:9、没有整页横纵滚动；50 活动时仅顶部总数改变，画布不增加高度。师生检查无新增控制台脚本异常。
- 原独立 3218 演示停服完整备份后升级：1 课堂、18 参与身份、54 提交，全部旧列逐表一致，54 行 `activity_id` 正确回填。之后在演示中追加一条可编辑判断题；课堂 ID 和固定链接保留。没有改动更早的 `output/local-preview` 或扣子生产。
- 完整日志、截图、数据库和备份保存在忽略的 `output/`，不提交 Git。仓库仅收录[脱敏摘要](evidence/validation-2026-10-13-v070.json)。本轮没有运行 Docker、修改扣子配置或发布生产。

## 复现

```bash
npm ci
npm test
npm run build
# 在独立测试数据库上；不要提交连接凭据。
TEST_DATABASE_URL=postgresql://127.0.0.1:55439/classroom_test npm test
node scripts/qa-server.js
```

浏览器进入 QA 的 `/teacher`，登录后添加第二道判断题，再复制学生链接。提交第一题、切换第二题，第二题应先保持锁定；提交后才展示自身统计。另添选择题和词云检查独立题目、选项和结果。检查删除确认提示；需要删除验证时仅操作专用测试课堂。将活动增至 50，学生页面仍应一屏显示；清空后师生显示空活动／等候，刷新和重启不恢复默认活动。

## 升级与回退

补充：扣子在应用启动前同步表结构，已有提交且缺少 `activity_id` 的生产库需要先完成[停写预迁移](DEBUGGING_COZE_DEPLOY_2026-10-13.md)。以下自动迁移说明以平台结构同步已经通过为前提；不能据此直接发布到未准备的旧库。

1. 安排停课窗口，停止所有旧实例写入并完整备份实际数据库。记录原课堂 ID、记录数量、版本和登录结果。SQLite 完整备份数据目录；PostgreSQL 使用一致性数据库备份。
2. 所有实例统一运行 0.7.0，保留原数据库、数据目录和生产环境配置；初始化自动升级，无需重建课堂或再次导入已有 PostgreSQL。
3. 在实际生产域名确认 `/api/health` 版本 0.7.0、正确存储和同步模式；核验原密码登录、固定链接、原提交及活动顺序，再用专用测试课堂演练增删和跨实例切换。
4. **不要让 0.6 及更旧代码与 0.7 同时读写升级后的数据库。** 新提交列和数组配置不支持旧写入方式；先停旧实例再切换，不能混用版本做滚动发布。
5. 回退时先停止新实例并另存升级后的记录，再恢复升级前的完整数据库备份和对应旧代码。只回退代码不够；升级后新增数据不会自动出现在旧备份中，先导出保存。删除活动不会修改历史备份或已导出文件。
