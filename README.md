# AI 共创课堂

[English](README.en.md) · [验证记录](TEST_REPORT.md) · [交接日志](TIMESTAMP_LOG.md)

一个老师、一节课堂、两个固定主题。老师控制学生页面总开关和课堂节奏，学生打开固定链接直接进入，并自动跟随当前主题。学生先独立填写，提交后才在右侧看到本主题的同学分享。

这是从[同频课堂反馈](https://github.com/bd4rex/tongpin-classroom-feedback)独立简化的项目，采用新的仓库与数据目录。保留 React、Fastify、SQLite 和 SSE 的实现方式，固定课堂流程，不包含通用题库、任务编辑器、模型配置或 AI 调用。

## 课堂流程

| 环节                         | 学生填写                                                     | 教师操作                       |
| ---------------------------- | ------------------------------------------------------------ | ------------------------------ |
| 一起发现：身边的人工智能应用 | 学校（下拉）、姓名、领域、应用场景、价值                     | 切换到一起发现，暂停／继续填写 |
| 一起设计：未来的人工智能应用 | 场景、基本功能；首次提交时补填学校和姓名，否则沿用已保存身份 | 切换到一起设计，暂停／继续填写 |

- 老师点击“复制学生端链接”后可多次转发；师生界面均不显示课堂码，学生打开链接即自动进入，不需要输入口令或点击加入。链接为 `/classroom/<课堂ID>`，一经生成便固定，切换主题、暂停、关闭、结束、刷新和重启都不会重置它。二维码也对应同一链接。
- 页面总开关控制学生是否看到活动。关闭时所有学生进入等候页；打开后跟随当前主题。课前等候、一起发现、一起设计同一时间只显示一个。
- 老师切到第二个主题时，全体学生自动进入第二个页面，包括没有提交第一份的学生。老师也能返回前一主题；学生没有自行切换主题的入口。
- 每个主题分别遵守“先提交，再看同学分享”。未提交者看到锁定提示，服务端也拒绝列表、搜索、分页读取；提交后自动解锁当前主题。完成发现不会解锁设计。
- 主要面向机房电脑，兼顾平板横屏和交互大屏；手机窄屏不作为专项适配目标。左侧填写或查看自己的作品，右侧以论坛式逐条列表展示姓名、学校、时间和回答。最新提交在前，每页 50 条，支持搜索。教师可随时查看两个主题的全部记录。
- 教师在“全班提交记录”中按主题、学校、姓名或内容组合筛选，点击行尾“删除”或勾选本页后“删除所选”（每次最多 50 份），确认后学生端同步移除。切换筛选、主题或页码会清空勾选，避免误删隐藏记录。确认框列出本次选中的姓名并提示删除不可恢复。
- 删除会永久清空作品正文，师生列表、搜索、作品数量和 CSV 导出都不再包含它。仅保留已提交标记，作者看到移除提示且不能再次提交本主题；原有的同学分享阅读资格保留。后续词云应使用正常提交的列表或导出数据，本次尚未增加词云功能。
- 暂停只停止填写，已解锁的分享仍可阅读；关闭页面或结束课堂会收起学生表单和分享。结束后统一显示结束页，教师仍可查看和导出记录。
- 每名参与者每个主题提交一次；同一请求重试不会重复计数，已提交内容不再编辑。未提交草稿暂存在当前浏览器标签页，切换主题或刷新可恢复；提交记录保存在数据库。
- 学生无需手动刷新。实时通知、断线重连会获取最新状态，另有约 6–7.5 秒轮询兜底。右上角分别显示“课堂实时同步”“课堂定时同步”或“连接中断，正在重试”；定时同步时仍可正常上课，变化通常在下一次轮询显示。实时通道连续 45 秒没有消息会自动重建，网络断开时无法保证同步。
- 教师“课堂工具”提供 CSV 导出和新一节课。先结束课堂或关闭页面，再开始新课；会为新课堂生成另一个固定链接，需要重新分享。旧链接继续对应原课堂并显示已结束，不会进入新课堂。旧记录保留在数据库，当前界面只查看和导出本节课，请切换前先导出。

## 本地运行

需要 Node.js 24 或更高版本。

```bash
npm ci
npm run build
npm start
```

学生入口：<http://localhost:3218/>；教师入口：<http://localhost:3218/teacher>。

第一次启动会在服务终端打印随机教师密码，请保存。学生通过老师分享的固定链接直接进入，不注册账号。访问根路径 `/` 会自动跳转到当前课堂的固定链接；重复打开同一链接会复用当前浏览器的学生身份。新课堂初始关闭学生页面，停留在课前等候。忘记教师密码时，先停止服务，再执行：

```bash
npm run password:reset
npm start
```

该命令打印新随机密码，并注销现有教师登录，不修改学生作品。开发模式使用 `npm run dev`。

## 学校下拉名单

`config/schools.json` 已按用户提供的名称及顺序配置以下 6 所学校。后续修改此数组并重启服务即可更新下拉选项：

```json
[
  "南京浦口区石桥中学",
  "南京市溧水区东庐初级中学",
  "无锡宜兴市丰义中学",
  "南通通州区兴仁中学",
  "南通通州区新坝初级中学",
  "南通海安市墩头镇吉庆初级中学"
]
```

支持 1–500 所学校，每项最多 100 个字符。学校必须从列表选择，服务端也会校验；已提交记录保留原学校名称。环境变量 `SCHOOLS_FILE` 可指定其他 JSON 文件。

## 校内运行与部署

默认监听 `0.0.0.0:3218`。让学生使用校内服务器地址访问同一服务；老师也应通过该地址进入 `/teacher`，以生成学生可访问的链接和二维码；正式传播时使用固定的服务器地址或域名，并在 `PUBLIC_URL` 中配置。课堂链接没有时效期限，但依赖该地址持续可访问、数据库保留原课堂。`localhost` 或 `127.0.0.1` 链接仅本机可用，页面会提示。

```bash
cp .env.example .env
```

按实际环境设置 `.env`：`PORT`、`HOST`、`DATA_DIR`、`SCHOOLS_FILE`；可用 `PUBLIC_URL` 固定学生实际访问的 HTTP(S) 地址，例如 `https://classroom.example.edu`，不要附加路径。`npm start` 和 `npm run dev` 自动读取 `.env`。`TEACHER_PASSWORD` 只在首次初始化时生效，不会覆盖已有密码。

复制链接优先使用 `PUBLIC_URL`；未配置时使用教师浏览器实际访问的地址，避免 HTTPS 代理后误用内部 HTTP 地址。HTTPS 反向代理仍应设置 `PUBLIC_URL` 为外部访问地址，以便同源写入校验正确。

校内 HTTP 可用；使用 HTTPS 时设置 `COOKIE_SECURE=true`。Nginx 示例见 [deploy/nginx.conf.example](deploy/nginx.conf.example)，SSE 需要关闭代理缓冲。

```bash
docker compose up -d --build
docker compose logs classroom
```

Docker 数据存储于命名卷 `classroom-data`，学校配置从宿主机 `config/` 只读挂载。首次密码可在日志中查看。修改学校名单后执行 `docker compose restart classroom`。本轮未实际构建或运行 Docker，也未部署到学校服务器。

## 部署后的连接与链接排查

- **定时同步正常，实时连接不可用**：检查 `/api/events?role=teacher` 是否被反向代理、压缩或缓存缓冲。正常响应是 `text/event-stream`，立即包含 `ready` 事件，每 20 秒有 `heartbeat`。Nginx 示例已给此接口单独关闭缓冲、压缩和缓存；托管平台也需允许流式响应。即使平台不支持长连接，约 6–7.5 秒一次的同步仍继续运行，页面不会把它误报成断网。
- **连接中断，正在重试**：状态接口也未能正常读取，应检查服务是否运行、网络以及浏览器中的 `/api/session` 响应。恢复后会自动切回定时或实时同步；教师登录过期则回到登录页。
- **学生旧链接找不到课堂，重新复制后可用**：比较两个链接中的课堂 ID。不同数据库或新课堂有不同 ID，本地预览链接也不能直接用于另一份线上数据库。线上更新必须保留原 `DATA_DIR` 和 SQLite 数据库；托管平台应挂载持久目录或数据卷，不能把数据库放在每次构建都会替换的临时目录。只更新代码并保留数据时，原课堂 ID 和链接不会变化。未知链接不会自动跳到另一节课。

0.4.1 已通过本地真实 HTTP 和浏览器故障模拟验证上述回退与恢复行为；具体线上代理配置和数据持久化仍需在实际部署环境核对。

## 数据与使用边界

- 姓名、学校和作品在**当前课堂已提交同一主题的学生之间公开**，且只在老师开放的当前主题中可读；加入页会提示。未加入或未提交者不能读取分享，教师操作需要密码。
- 学生身份依据当前浏览器 Cookie。清除 Cookie、换浏览器或换设备会成为新参与者；不做真实身份验证和跨设备去重。
- 数据默认在 `data/classroom.sqlite`，使用 SQLite WAL。停服后完整备份 `data/`；不要只复制运行中的主数据库文件。运行数据、密码、环境文件、依赖和截图均排除在 Git 外。
- 先前已分享的 `/?code=...` 链接仍会自动跳到对应课堂的新固定链接；不再提供输入课堂码的页面。密码及学生作品不会因为入口变更而重置。
- 从 0.1 升级会自动增加课堂状态字段，保留课堂、身份和作品。原两个开关同时开放时进入设计；只有发现开放时进入发现；都关闭时进入课前等候。升级前请停服备份数据目录。
- 升级到 0.4 会自动为提交增加删除时间字段，原有作品保持正常显示。删除时正文清空为 `{}`，只保留参与者、主题、提交时间和删除时间作为防重复提交的标记；不能通过接口恢复原文。独立的历史备份和此前导出的文件不随之修改。
- 单服务进程部署，不使用多个实例共享数据库；每次状态变更合并 SSE 通知，列表分页以限制单次响应。实际课堂容量需要在目标设备和网络上实测。
- 不调用外部 AI、不需要模型密钥。课堂里讨论 AI，不产生模型调用费用。
