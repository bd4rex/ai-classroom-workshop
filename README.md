# AI 共创课堂

[English](README.en.md) · [部署手册](deploy/coze.md) · [活动管理记录](deploy/DEBUGGING_ACTIVITIES_2026-10-13.md) · [最新部署排查](deploy/DEBUGGING_COZE_DEPLOY_2026-10-13.md) · [验证记录](TEST_REPORT.md) · [交接日志](TIMESTAMP_LOG.md)

一个老师、一节课堂，自由安排判断题、选择题和词云活动。每节课最多 50 个活动，同类型可重复添加。老师控制学生页面总开关和课堂节奏，学生打开固定链接自动跟随；每个活动先独立提交，随后在右侧看到全班饼图或词云。

这是从[同频课堂反馈](https://github.com/bd4rex/tongpin-classroom-feedback)独立简化的项目，采用新的仓库与数据目录。React + Fastify，本地单进程支持 SQLite 和 SSE，多实例使用共享 PostgreSQL 和短请求同步。不调用外部 AI，也不包含通用题库、评分或教务管理。

## 课堂流程

| 活动   | 学生输入                             | 提交后的右侧结果         |
| ------ | ------------------------------------ | ------------------------ |
| 判断题 | 正确／错误，单选                     | 两种选择的人数与比例饼图 |
| 选择题 | 2–6 个选项，单选                     | 各选项人数与比例饼图     |
| 词云   | 1–3 个词，用逗号分隔，每词最多 12 字 | 全班关键词词云           |

- 首次实际提交时选择学校、填写姓名，之后沿用。每个活动提交一次；请求重试不重复计数，草稿保存在当前浏览器标签页。
- 老师在“本节课的活动”添加三种类型的活动，逐项编辑、上移、下移或删除，内置可替换的示例。题干最多 60 字，选项最多 24 字；收到本题第一份提交后锁定内容，避免同一统计混入不同题目。删除全部提交也不会解除锁定；需要换题可另添同类型活动。
- 删除活动需确认，会永久清除该活动及其全部提交（包括已移除回执）。删除当前活动后全班回到等候页；其他活动不受影响。活动清空后保持空列表，可随时重新添加。结束后的课堂不能继续编辑，需开始新课堂。
- 老师控制页面总开关、课前等候、当前活动、暂停／继续和结束。学生没有自行切换入口，未提交上一活动也直接跟随下一活动。暂停保留已解锁结果；关闭页面或结束课堂收起全部作答和图表。
- **每个活动独立执行“先提交，再看结果”**。提交第一道判断题不会解锁第二道判断题或其他活动；服务端校验身份、当前活动、页面开关和本题提交回执。图表汇总当前课堂全部有效提交，不受教师列表的每页 50 条限制。
- 饼图按真实票数绘制，百分比独立四舍五入到 1 位小数；相同票数显示相同比例，合计可能为 99.9% 或 100.1%。不判断答案对错、不自动评分。
- 词云按参与者计数，同一人重复词只计一次；去除首尾空格，合并全角／半角和英文字母大小写。服务端返回前 60 个高频词，固定画布内优先放置高频词，并显示“展示数量／不同词总数”。完整有效内容仍可在教师列表和 CSV 查看。
- **学生端固定 16:9**：以 1440 × 810 为基准按窗口宽高等比缩放，非 16:9 屏幕居中留边，题目、作答、图表和按钮始终在同一屏内。顶部只显示当前活动序号和总数，活动增多也不挤占作答区域。提供浏览器全屏按钮。主要面向机房电脑、平板横屏和交互大屏；教师后台按笔记本常规布局，允许滚动，手机窄屏不作专项适配。
- 老师可反复复制分发 `/classroom/<课堂ID>` 固定链接，二维码使用同一地址。师生界面不显示课堂码，也不要求输入课堂码；切换活动、暂停、结束、刷新和重启不改变本课堂链接。
- 教师按活动、学校、姓名或内容组合筛选，可单条删除或勾选当前页批量删除，每次最多 50 份。确认框提示永久删除；删除后正文清空，不再进入列表、饼图、词云或 CSV，只保留防重交回执。作者不能重交，但保留本题查看结果的资格。
- PostgreSQL 多实例模式每 2.5–3.5 秒自动同步；SQLite 单进程保留 SSE 和轮询兜底。图表跟随数据版本更新，学生无需刷新。
- “课堂工具”提供 CSV 导出和新课堂，导出包含活动 ID、序号和题干以区分同类型题目。先结束或关闭当前课堂再新建，新课堂继承活动顺序和题目配置、清空本节答题统计并获得新链接；旧数据仍保留，旧链接显示原课堂已结束。当前界面仅查看和导出当前课堂，请切换前导出。
- 旧“一起发现／一起设计”课堂及记录保留兼容；有记录或正在进行的旧活动仍显示在教师端，旧活动继续使用原表单／列表布局。首次初始化提供三个示例活动，升级不会重置密码或原固定链接。

## 本地运行

需要 Node.js 24 或更高版本。

```bash
npm ci
npm run build
npm start
```

教师入口：<http://localhost:3218/>（自动跳转到 `/teacher`）。学生使用教师登录后复制分发的固定课堂链接。

第一次启动会在服务终端打印随机教师密码，请保存。学生通过老师分享的固定链接直接进入，不注册账号。访问根路径 `/` 会进入教师页面：未登录时显示教师登录，已登录时显示工作台，不会自动加入课堂。重复打开教师分享的同一课堂链接会复用当前浏览器的学生身份。新课堂初始关闭学生页面，停留在课前等候。忘记教师密码时，先停止服务，再执行：

```bash
npm run password:reset
npm start
```

该命令打印新随机密码，并注销现有教师登录，不修改学生作品。开发模式使用 `npm run dev`。

## 学校下拉名单

`config/schools.json` 已按用户提供的名称及顺序配置以下 6 所学校。后续修改此数组并重启服务即可更新下拉选项：

```json
[
  "南京浦口区石桥中学",
  "南京市溧水区东庐初级中学",
  "无锡宜兴市丰义中学",
  "南通通州区兴仁中学",
  "南通通州区新坝初级中学",
  "南通海安市墩头镇吉庆初级中学"
]
```

支持 1–500 所学校，每项最多 100 个字符。学校必须从列表选择，服务端也会校验；已提交记录保留原学校名称。环境变量 `SCHOOLS_FILE` 可指定其他 JSON 文件。

## 校内运行与部署

默认监听 `0.0.0.0:3218`。让学生使用校内服务器地址访问同一服务；老师也应通过该地址进入 `/teacher`，以生成学生可访问的链接和二维码；正式传播时使用固定的服务器地址或域名，并在 `PUBLIC_URL` 中配置。课堂链接没有时效期限，但依赖该地址持续可访问、数据库保留原课堂。`localhost` 或 `127.0.0.1` 链接仅本机可用，页面会提示。

```bash
cp .env.example .env
```

按实际环境设置 `.env`：`PORT`、`HOST`、`DATA_DIR`、`SCHOOLS_FILE`；可用 `PUBLIC_URL` 固定学生实际访问的 HTTP(S) 地址，例如 `https://classroom.example.edu`，不要附加路径。`npm start` 和 `npm run dev` 自动读取 `.env`。`TEACHER_PASSWORD` 只在首次初始化时生效，不会覆盖已有密码。

复制链接优先使用 `PUBLIC_URL`；未配置时使用教师浏览器实际访问的地址，避免 HTTPS 代理后误用内部 HTTP 地址。HTTPS 反向代理仍应设置 `PUBLIC_URL` 为外部访问地址，以便同源写入校验正确。

校内 HTTP 可用；使用 HTTPS 时设置 `COOKIE_SECURE=true`。Nginx 示例见 [deploy/nginx.conf.example](deploy/nginx.conf.example)，SSE 需要关闭代理缓冲。

```bash
docker compose up -d --build
docker compose logs classroom
```

Docker 数据存储于命名卷 `classroom-data`，学校配置从宿主机 `config/` 只读挂载。首次密码可在日志中查看。修改学校名单后执行 `docker compose restart classroom`。本轮未实际构建或运行 Docker，也未部署到学校服务器。

## 扣子与多实例部署

0.5.0 支持共享 PostgreSQL、跨实例会话与课堂状态、2.5–3.5 秒短请求同步。本地两个独立服务进程通过 500 人同时加入及两轮集中提交，扣子开发 PostgreSQL 40 项检查通过；这不等于扣子生产容量验收。新项目落地、已有项目迁移、配置模板和回退见 [扣子部署手册](deploy/coze.md)。本次故障、失败尝试、修复和复测保存在 [完整排查记录](deploy/DEBUGGING_2026-09-23.md)，脱敏压测结果也随代码保留。

## 部署后的连接与链接排查

- **PostgreSQL 显示定时同步**：这是正常工作方式，不会建立 SSE，也无需等待它恢复。
- **SQLite 定时同步正常，实时连接不可用**：检查 `/api/events?role=teacher` 是否被反向代理、压缩或缓存缓冲。正常响应是 `text/event-stream`，立即包含 `ready` 事件，每 20 秒有 `heartbeat`。Nginx 示例已给此接口单独关闭缓冲、压缩和缓存；托管平台也需允许流式响应。即使平台不支持长连接，约 6–7.5 秒一次的同步仍继续运行，页面不会把它误报成断网。
- **连接中断，正在重试**：状态接口也未能正常读取，应检查服务是否运行、网络以及浏览器中的 `/api/session` 响应。恢复后会自动切回定时或实时同步；教师登录过期则回到登录页。
- **学生旧链接找不到课堂，重新复制后可用**：比较两个链接中的课堂 ID。不同数据库或新课堂有不同 ID，本地预览链接也不能直接用于另一份线上数据库。SQLite 单进程更新必须保留原 `DATA_DIR`；扣子等多实例平台应迁移到共享 PostgreSQL。不能把数据库放在实例临时目录。只更新代码并保留数据时，原课堂 ID 和链接不会变化。未知链接不会自动跳到另一节课。

0.4.1 已通过本地真实 HTTP 和浏览器故障模拟验证上述回退与恢复行为；具体线上代理配置和数据持久化仍需在实际部署环境核对。

## 数据与使用边界

- 0.7 增加独立活动 ID，将“每人每类型一次”升级为“每人每活动一次”，保留原课堂、密码和记录。升级需先停止所有旧实例并备份，所有实例统一更新；不能混用 0.6 及更旧代码读写升级后的库，也不能仅回退代码。见[升级与回退记录](deploy/DEBUGGING_ACTIVITIES_2026-10-13.md)。

- 新活动的学生端只展示本人身份和全班汇总；教师可查看各人的姓名、学校与提交。旧发现／设计活动仍将作品分享给已提交同一主题的同学。未加入或未提交者不能读取结果，教师操作需要密码。
- 学生身份依据当前浏览器 Cookie。清除 Cookie、换浏览器或换设备会成为新参与者；不做真实身份验证和跨设备去重。
- 数据默认在 `data/classroom.sqlite`，使用 SQLite WAL。停服后完整备份 `data/`；不要只复制运行中的主数据库文件。运行数据、密码、环境文件、依赖和截图均排除在 Git 外。
- 先前已分享的 `/?code=...` 链接仍会自动跳到对应课堂的新固定链接；不再提供输入课堂码的页面。密码及学生作品不会因为入口变更而重置。
- 从 0.1 升级会自动增加课堂状态字段，保留课堂、身份和作品。原两个开关同时开放时进入设计；只有发现开放时进入发现；都关闭时进入课前等候。升级前请停服备份数据目录。
- 升级到 0.4 会自动为提交增加删除时间字段，原有作品保持正常显示。删除时正文清空为 `{}`，只保留参与者、主题、提交时间和删除时间作为防重复提交的标记；不能通过接口恢复原文。独立的历史备份和此前导出的文件不随之修改。
- SQLite 限单进程且必须持久存储；多个实例使用同一 PostgreSQL 数据库。共享模式每实例最多 10 个数据库连接，状态变化以版本号驱动列表刷新，学生 Cookie 临近过期才续期写库。实际容量需在目标网络和资源上验收。
- 不调用外部 AI、不需要模型密钥。课堂里讨论 AI，不产生模型调用费用。
